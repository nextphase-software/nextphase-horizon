BRIEF VERSION: 0003-W1 v1 (2026-10-17)

# 0003-W1 — Answer operations: sustainable spending, levers, input impact and today's-dollar values

## Outcome

Horizon can answer, for any supported household:
- **What can be spent?** The highest after-retirement spending the plan carries without a shortfall.
- **What moves the result most?** A fixed set of one-change levers, ranked.
- **Which rough inputs matter?** Each input marked rough, ranked by how far it can move the answer.

Balances and shortfalls also come out in today's dollars. Every answer comes from the application layer, so the command line, the browser module and later adapters return identical results.

## Deliverables

1. **`sustainable_spending(input)`** (decision 0012, items 1–2; amendment A2–A3) in `horizon-app`.
   - It returns the highest whole-dollar after-retirement spending, in today's dollars, with zero total shortfall.
   - The search follows amendment A2 exactly, including its two verification runs and its flags:
     - `at_or_above_cap`, at $10,000,000 a year;
     - `shortfall_with_no_retirement_spending`.
   - It reports the result, the flag (or null), the run count, the entered amount and headroom (A1), and the full run at the result.
   - The search's run function is replaceable in tests.
   - A nominal after-retirement amount returns `SPENDING_BASIS_UNSUPPORTED` (unsupported); a failed verification returns `SPENDING_SEARCH_NOT_MONOTONIC` (invalid).
2. **`levers(input)`** (items 3–4; amendment A1, A5): the six levers `retire_earlier`, `retire_later`, `spend_lower`, `spend_higher`, `return_lower`, `return_higher`, in that order, each offered or skipped by A5.
   - **Per lever:** its JSON Pointer change list, sustainable spending and flag, headroom, effect (the change in headroom), first shortfall age at the entered amounts, ending total in today's dollars, and status.
   - **Ranking:** a ranking by |effect|, and `what_moves_most`: up to three kinds (`retirement_date`, `spending`, `return`) ranked by their largest |effect|.
   - **Ties:** both follow item 3's order.
3. **`input_impact(input, rough)`** (item 5; amendment A1, A4):
   - each rough item is `{path, low?, high?}`, with default ranges by path;
   - per item it reports low, high, headroom at each, and impact;
   - items are ranked by impact;
   - an unknown path without a range returns `IMPACT_RANGE_REQUIRED` (invalid); a malformed pointer returns `SCENARIO_POINTER_INVALID`.
4. **Today's-dollar fields in the federal-tax run** (item 6; amendment A6): `closing_today` per account; `total_closing`, `total_closing_today` and `shortfall_today` per year; `ending_total_today` and per-balance `balance_today` in comparison summaries. The pre-tax ledger used by earlier reference values is unchanged.
5. **Contracts** (item 7):
   - **Model version:** `horizon-engine-0.4.0`; the rule set stays `us-single-federal-tax-v3`.
   - **New published schemas,** generated with `schemars`, each with a drift test:
     - `run-output.v2`, `comparison.v2` and `export.v2` (the export envelope keeps `export_format_version: 1` and embeds run output v2);
     - `sustainable-spending.v1`, `levers.v1` and `input-impact.v1`.
   - **The v1 schema files** are left unchanged as the record of 0.3.0 outputs.
   - **New error codes** in `docs/model/error-codes.md`.
6. **Command line:**
   - `horizon spend <name|path>`;
   - `horizon levers <name|path>`;
   - `horizon impact <name|path> <rough.json>`, where `rough.json` is a JSON array of rough items.

   Each prints canonical JSON and a newline, with exit codes 0 complete, 3 partial, 1 invalid and 2 unsupported, following the status of the run at the result. Errors use the existing envelope. The command line contains no calculation rule.
7. **Fixtures:** `answers-working-61`, `answers-working-61-retire-later`, `answers-underfunded` and `answers-cap`, exactly as given under `households` in `docs/briefs/0003-W1-reference-values.json`.
8. **WebAssembly parity:**
   - golden run and export outputs are regenerated by the existing generator for model 0.4.0, never hand-edited;
   - `horizon-parity` also runs this milestone's reference values (sustainable spending, levers, input impact, today's values) on `wasm32-unknown-unknown` under Node.js 24.22.0, byte-identical to native.
9. **Documentation:**
   - `docs/model/answers.md` describes the three operations, the today's-dollar fields and their fixtures;
   - `AGENTS.md` and `README.md` list the full cumulative validation commands;
   - `docs/model/dependencies.md` stays accurate. No new dependency is expected; any new crate requires escalation.
